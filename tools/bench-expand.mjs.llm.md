# `tools/bench-expand.mjs` — заметка для LLM

> Сайдкар к `bench-expand.mjs`: что здесь происходит, чтобы отлаживать, не перечитывая файл целиком.
> Источник истины — код и SPEC.md; заметка — карта. Меняешь файл — обнови заметку в том же коммите.

## Назначение
Замер цены предела раскрытия экземпляров (`MAX_EXPANDED_NODES` = 50 000) и раскладки после правки:
полная раскладка с образцами и без них (`shapes:false`, как до круга 52) и по месту (`solveAfter`).

## Главное
- `measure(coreUrl, sizes)` — сборка документа и все замеры; одна функция, в браузер уходит текстом
  (`page.evaluate`).
- `build(total)` — мастер из 50 узлов (колонка: тексты и прямоугольники), экземпляры сеткой с переносом.
- Строки таблицы: 10/20/35/50 тыс. раскрытых узлов; «смешанный» — 1250 карточек по 4 слоя рядом с экземплярами.
- Колонки: правка мастера (текст `mt1`, видят все экземпляры) и правка вне (имя сетки `G`).

## Поток данных
Для каждой правки: `solve(doc)` (раскрытие прежнего документа в кеше, как в оболочке) →
`solve(doc, {incremental:true})` → свежая правка → замер `run(prev, next)`; лучшее из трёх, мс.

## Инварианты
- Каждый замер — на свежей правке (новый объект мастера): раскрытие после правки мастера — часть цены.
- Прежняя геометрия для `solveAfter` готовится вне замера: она одноразовая.

## Подводные камни
- Шум машины ±20–30 %: сравнивать ветки подряд на одной машине, по нескольку прогонов.
- У самого предела `console.warn` про нераскрытые экземпляры — ожидаемо (в Node глушится).
- `--browser` поднимает document service на свободном порту и Chromium (Playwright из репозитория).

## Отладка
`env -u NODE_OPTIONS node tools/bench-expand.mjs` (Node) и `--browser` (Chromium с настоящим измерением текста).
