# `tools/critic/format-mutants.mjs` — заметка для LLM

> Сайдкар к `format-mutants.mjs`: что здесь происходит, чтобы отлаживать, не перечитывая файл целиком.
> Источник истины — код и SPEC.md; заметка — карта. Меняешь файл — обнови заметку в том же коммите
> (конституция, принцип VII; проверка — `node tools/sidecars.mjs`).

## Назначение
Инструмент критика (круг 45, по `r44/mut.py`, `r44/mut2.py`): мутанты правил ядра против отпечатка
формата `FORMAT_SIGNATURE` (SPEC §8.3, §9.20). Показывает дыры, где две сборки одной версии движка
разойдутся на одном журнале. Запускается руками, в `npm test` не входит.

## Главное
- `MUTANTS` — список `[имя, [[было, стало, сколько раз]], проба]`. Каждая строка замены должна
  встретиться в `src/core.js` ровно указанное число раз, иначе исключение (мутант устарел).
- Каждый мутант пишется отдельным файлом `m<N>.mjs` во временный каталог и импортируется.
- «Пойман» — `FORMAT_SIGNATURE.hash` мутанта отличается от ядра.
- `setOn(core, path, value)` — проба: `set` поля на первой доске демо-документа, итог «принято» или текст отказа.
- `--only <часть имени>` — прогнать только подходящие мутанты.

## Поток данных
Читает `src/core.js`, пишет мутантов во временный каталог (удаляется в `finally`), печатает `console.table`.

## Инварианты
- Выход 1 — есть мутант, которого отпечаток не ловит, а проба показывает другое поведение (или пробы нет).
- Мутант без пробы и непойманный считается дырой.

## Подводные камни
- Имена файлов мутантов — по номеру: кириллица в имени склеивала мутантов в один модуль.
- Правка текста правил в ядре ломает строки замены — обновите их здесь и в `tools/critic/fmtloss.mjs`.
- Проба глушит `console.warn` на время `applyOps`.

## Отладка
`env -u NODE_OPTIONS node tools/critic/format-mutants.mjs [--only opacity]`; смотрите столбцы
«отпечаток», «ядро», «мутант_проба».
