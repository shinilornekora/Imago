# `src/core.js` — заметка для LLM

> Сайдкар: карта файла для отладки. Источник истины — код и SPEC.md. Меняешь файл — обнови заметку в том же коммите (конституция, принцип VII; проверка — `node tools/sidecars.mjs`).

## Назначение
Движок Imago (≈13 тыс. строк, один ES-модуль без зависимостей): модель документа, операции и их проверка, слияние транзакций, решатель геометрии (раскладка), валидаторы, цвет и контраст, тема доски, компоненты и раскрытие экземпляров, сцена (SVG + ввод, класс `Stage`) и снимок без браузера. **Один и тот же модуль** исполняют браузер, Document service (DSLTS — `rebase`/`applyOps`), Orchestrator и его воркеры (§8.3 «движок один»). Шапка файла — контракт и правила миграций; экспорт — один блок `export {…}` в конце файла (≈13102) с комментариями по кругам.

## Поток данных
Документ `Doc = {id, version, root, nodes, tokens, meta}` (§1.2) → `applyOps` (правка) → `solve`/`solveAfter` (геометрия; раскрытые экземпляры — в `geo.expanded`, не в `doc.nodes`) → `validate` → `Stage.render(doc, geo, state)` или `renderSVG`. На сервере: транзакция → `rebase` поверх головы → `applyOps`/`applyBatches` → журнал.

## Инварианты
- Детерминизм: `solve(doc)` — чистая функция документа; все быстрые пути (`solveAfter`, `solveNext`) обязаны давать тот же `hashGeometry`, что полная раскладка (бенч и тесты это сверяют).
- Операций пять и они не растут (§5.2); новые возможности — новые поля/типы, а не новые операции.
- Любое изменение формата документа (новое поле, тип, значение перечисления, поведение отрисовки) — только с подъёмом `ENGINE_VERSION` и строкой в `FORMAT_HISTORY` (`test/core-r43.test.mjs`, тест печатает строку, которую надо вставить); при этом `liftOps` должен поднимать записи прежнего движка.
- Шкалы читаются числом ТОЛЬКО через `resolveScale`/`resolveLayout`/`resolveRadius`; читать `gap`/`padding`/`radius` как числа нельзя.
- Правки компонентов, шкал, дублирования возвращают ОПЕРАЦИИ и документ не меняют.
- Раскрытие не больше `MAX_EXPANDED_NODES`; сверх — заглушки (`DEGRADED_INSTANCE_NODES`).

## Подводные камни
- Ключи вида `constructor`/`__proto__` — не id узла (`isNodeId`, круг 25).
- Кеш измерений текста залипает на системном шрифте, если не сбросить после загрузки гарнитур (`onMeasureEpoch`).

## Раскладка по месту и кеш экземпляров (круги 54, 61, 62)

Раздел потока «долги 45 / раскладка» (PR #8, #15, #18). Строки — примерные.

### Назначение
Документ с экземплярами компонентов раскладывается так же, как без них, и побитно равен эталону
`solve(doc, {shapes:false})`. Правка у предела в 50 000 раскрытых узлов не пересчитывает и не
пересоздаёт того, что не изменилось.

### Главное
- `expandCache` (~2454) — WeakMap «объект экземпляра → запись»: `{deps, nodes, size, shape, flat, master, syn}`.
  `deps` — плоский список `[id, узел, …]` (библиотека, мастер, поддерево мастера). `syn` — раскрытые узлы по
  местам списка поддерева; `master` и `syn` есть только у записи без вложенных экземпляров (`flat`).
- `shapeSig` / `shapeHeight` (~2465/2485) — ключ формы и высота поддерева (круг 54).
- `expandOne` (~2533) — раскрытие одного экземпляра. Круг 62: `stat.old` — прежняя запись того же экземпляра;
  узел мастера тот же объект на том же месте `deps` → тот же раскрытый узел (`old.syn[j]`).
- `expandDoc` (~3025) → `expandAll(doc, merge)` (~3035): раскрытие всех экземпляров, общая карта
  «документ + раскрытые» (`merged`) и проверка коллизий id — одним проходом (`put`). Результат:
  `{nodes, count, shapes, collide, deep, fresh, used, parts, skipped?}`.
- `boardDepth` (~3164) — глубина узла под доской (предел `MAX_DEPTH`, флаг `deep`).
- `placeNode` (~7001): чистое поддерево → `copyPlaced` из прежней геометрии; экземпляр известной формы →
  `copyShape` по образцу `shapeOf`.
- `SOLVE_MEMO` (~7144) — WeakMap «geo → память»: `{doc, base, ex, size, nodes, seq, collide, deep, fn, epoch, meas, flow, span}`.
  `nodes` — общая карта, `base` — документ, от которого она собрана (после `solveCarry` `doc` уходит вперёд, `base` — нет).
- `solveWith` (~7152) — общий решатель; `seed` — раскладка по месту, `pre` — готовое раскрытие.
- `solveAfter` (~7260) — пути: `quickAfter` (круг 61, правка вне экземпляров, без раскрытия) →
  `changedParts` + `dirtyOf` с правкой карты на месте (круг 62) → прежний `dirtyAfter` (сравнение двух
  карт целиком). Хвост у всех — `afterDirty` (~7317).
- Для тестов: `solveShapeCopies()` (счётчик копий образца), `solveMemoMap(geo)` (карта памяти и её размер).

### Поток данных
`applyOps` → новый doc (неизменённые узлы — те же объекты) → `solveAfter(prevGeo, prevDoc, nextDoc)`:
память prevGeo → (быстрый путь | `expandAll` → изменённые id по `ex.parts` → грязные = изменённые +
предки в обеих версиях → правка `memo.nodes` на месте) → `afterDirty`: грязного больше половины —
полная раскладка с готовым раскрытием, иначе по месту → новая geo с новой памятью; память prevGeo удалена.

### Инварианты
- Узлы документа неизменяемы: изменённый узел — новый объект. На этом стоят все сравнения по тождеству.
- Раскрытый узел — функция от узла мастера, экземпляра и пропсов (от экземпляра и корня мастера).
- Коллизия id (раскрытый не-корень с id узла документа или двойная запись) → `collide`: образцов нет,
  `solveAfter` — полная раскладка.
- Карта памяти правится на месте только когда `memo.base === prevDoc`; после этого память prevGeo удаляется.
- `geo.order` — только настоящие узлы документа; раскрытые — в `seq` и `geo.expanded`.

### Подводные камни
- Ветка от старой геометрии (её память уже отдана) — полная раскладка: верно, но медленно.
- Записи `expandCache` общие для всех версий документа с тем же объектом экземпляра: раскрытие другой версии
  перезаписывает запись, и переиспользование в следующей правке меньше (верно, но медленнее).
- Правка вне экземпляров (быстрый путь) раскрытия не зовёт и записи кеша не поправляет.
- Перенос предка меняет глубину экземпляра без смены его объекта — отсюда флаг `deep`.
- Остаток правки мастера у предела (~130 мс) — копии образца и запись раскрытых узлов в карты. Опробовано
  и отброшено: переиспользовать прежние прямоугольники в копиях, раскладка по месту без копий (SPEC §18.8).

### Отладка
- Эталон: `hashGeometry(solveAfter(...)) === hashGeometry(solve(next, {shapes:false}))`, раскрытие — против
  `expandDoc(JSON.parse(JSON.stringify(next)))` (копия мимо кешей).
- `expandDoc(next).fresh` — сколько раскрыто заново; `solveMemoMap(geo)` — карта памяти после правки.
- Замеры: `node tools/bench-expand.mjs [--browser]`, `node tools/bench-stage.mjs`.
