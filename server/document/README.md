# Document service

Процесс «документ» из SPEC §8.1: модули **DSLR** (чтение), **DSLTS** (секвенсор — единственный
писатель) и **Hub** (рассылка по WebSocket) в одном процессе Node 22, без фреймворков.
Контракт — SPEC §9 (укрепление круга 23 — §9.8, круг 24 — §9.9): он нормативен и для клиента `src/sync.js`.

```
server/document/
  index.js              вход: окружение, сборка модулей, graceful shutdown; export start(opts)
  http.js               маршруты §9.2 (node:http), статика клиента для прогонов без nginx
  hub.js                WebSocket §9.3 (пакет ws): hello → догон → живой поток, presence, ping/pong
  dslr.js               чтение: open (снимок + хвост), since (догон или gone со снимком)
  dslts.js              секвенсор §9.4: голова в памяти, мьютекс, rebase → applyOps → commitTx → снимок
  errors.js             DocError → {error:true, code, message, retryable, detail?} — одно тело для HTTP и WS
  limits.js             все пределы и умолчания (клиент держит те же в src/sync.js LIMITS)
  storage/pg.js         PostgreSQL (pg.Pool с дедлайном), LISTEN/NOTIFY, раннер миграций
  storage/migrations/   NNN_имя.sql|mjs: 001 схема · 002 chain и эпоха · 003 chain старого журнала пачками · 004 traces
  storage/memory.js     тот же интерфейс в памяти (с уведомлениями и backup/restore) — тесты и соло-режим
  storage/committed.js  форма записи журнала, chain, выжимка dropped — общие для адаптеров
```

Движок — `src/core.js` без изменений: `rebase`, `applyOps`, `collectTombstones`, `hashDoc`,
`createDoc`, `ENGINE_VERSION`. Тот же модуль исполняется на клиенте, поэтому картинка
совпадает (§8.3 «движок один»).

## Запуск

```sh
npm install                       # pg, ws
DATABASE_URL=postgres://imago:imago@127.0.0.1:5432/imago node server/document/index.js
# или: npm run server
```

| переменная | по умолчанию | что |
|---|---|---|
| `PORT` | `8080` | HTTP и WebSocket на одном порту (`/api`, `/ws`); `0` — случайный |
| `HOST` | `0.0.0.0` | адрес |
| `DATABASE_URL` | — | Postgres; не задан — хранилище в памяти (данные живут до перезапуска) |
| `DB_TIMEOUT_MS` | `8000` | дедлайн обычного запроса к базе (statement_timeout + query_timeout); миграции — без него |
| `SNAPSHOT_EVERY` | `50` | снимок раз в N транзакций (асинхронно, после ответа); `0` — только при создании |
| `SNAPSHOT_KEEP` | `5` | сколько последних снимков хранить; снимок seq 0 (затравка) не удаляется никогда |
| `PRESENCE_TTL_MS` | `45000` | присутствие без вестей столько — `left` (клиент шлёт сердцебиение раз в 15 с) |
| `INTERNAL_TOKEN` | — | токен `POST /api/internal/traces` (заголовок `X-Internal-Token`); не задан или `change-me` — 403 |
| `STATIC_DIR` | — | каталог клиента (`index.html`, `app.js`, `styles.css`, `src/*.js`) — раздаётся с верными MIME, чтобы гонять без nginx: `STATIC_DIR=. node server/document/index.js` из корня репозитория |

Миграции применяются при старте: файлы `storage/migrations/NNN_имя.sql|mjs` по порядку,
учёт в `schema_migrations`, отдельное соединение под advisory-lock (два экземпляра на
одной базе не мешают друг другу), каждая — своя транзакция без дедлайна обычных
запросов; `.mjs` режет тяжёлую работу на пачки. Останов по `SIGTERM`/`SIGINT`: сокеты
закрываются кодом 1001, новые транзакции получают 503, снимки в полёте дописываются, пул
закрывается.

Несколько экземпляров над одной базой работают: номер и якорь (`head_chain`) выдаёт
`UPDATE projects SET head_seq = head_seq + 1, head_chain = sha256(…) … RETURNING` в одной
транзакции базы с `INSERT` в журнал и `NOTIFY imago_doc`; остальные экземпляры по
уведомлению дочитывают хвост и рассылают его своим сокетам. Экземпляр, чья голова в памяти
отстала, получает «не тот» номер, перечитывает хвост и сливает заново (до 12 попыток,
дальше 503 — клиент держит очередь). Голова, которая оказалась ВПЕРЕДИ базы или с другой
цепочкой, — признак отката базы из бэкапа: эпоха меняется, сокеты проекта закрываются
кодом 4410, клиенты переоткрываются со снимком и переигрывают свои правки (SPEC §9.8).
Под нагрузкой (два экземпляра, 30 клиентов, один проект) попытки кончаются у ~0,2 %
транзакций — 503, клиент повторяет (цифры — SPEC §9.9).

Присутствие ходит между экземплярами (§9.9) по отдельному каналу `imago_doc_presence`:
эфемерные `NOTIFY` через соединение слушателя (не через пул), с id экземпляра против эха;
выделение режется до 200 id и под предел NOTIFY (`truncated: true`); `left` — при закрытии
сокета, по TTL (45 с без вестей), при остановке экземпляра (`bye`) и при его падении (TTL
записей чужого экземпляра). Слушатель LISTEN после обрыва переподключается (200 мс → … →
10 с) и сверяет все головы с базой: пропущенное за обрыв дочитывается.

## Быстрая проверка

```sh
curl -s localhost:8080/api/health
curl -s -X POST localhost:8080/api/projects -H 'content-type: application/json' -d '{"name":"Проба"}'
curl -s localhost:8080/api/projects/<id> | head -c 300
curl -s -X POST localhost:8080/api/projects/<id>/tx -H 'content-type: application/json' -H 'X-Author: Аня' \
  -d '{"tx_id":"tx_1","base_seq":0,"engine":1,"ops":[{"op":"set","id":"<id доски>","path":"name","value":"Главная"}]}'
curl -s 'localhost:8080/api/projects/<id>/ops?since=0'
```

Имя в `X-Author` не-ASCII шлите в percent-encoding (`encodeURIComponent`): заголовки —
latin1, а `fetch` в браузере не-latin1 значение отвергает.

## Что важно знать клиенту (уточнения к §9)

* `hello.project` — сводка `{id, name, kind, head_seq, updated_at}`, не строка-id.
* Сокет без `since` — только живой поток (клиент открыл проект по HTTP и знает голову).
  `since=-1` — «ничего не знаю»: придёт `gone` со снимком. После `gone` по сокету сразу
  идёт хвост за снимком до головы; после HTTP `410` клиент сам просит `ops?since=snapshot.seq`.
* `gone`/`410` — когда `since < 0`, `since` впереди головы, хвост не начинается сразу за
  `since`, или присланный `tip` не совпал с журналом (SPEC §9.8: таблица разбора).
* Повтор своей `tx` по сокету (после разрыва) отвечает рассылкой `tx`, если этот сокет её
  ещё не получал, иначе — `{type:'ack', tx_id, seq, chain, existing:true}`. Клиенту без
  `tip`, `epoch` и `proto=2` в адресе (круг 22, `ack` не знает) вместо `ack` —
  `error {code:'duplicate', retryable:false, existing:true, tx_id, seq}`.
* `presence` — `{type, client, author, selection (≤ 200), board?, truncated?, busy?, queued?, at}`;
  `busy`/`queued` (агент работает над командой человека) — как прислал клиент, булево или
  число. Сердцебиение — раз в 15 с; тишина 45 с — `left`.
* Читатель, у которого неотправленного больше 32 МиБ, закрывается кодом 4503 — догонит с `since`.
* Хвост — страницами (`more: true` — есть ещё); `?head=1` — только голова; `?lean=1` — без
  документа снимка; полный снимок — под семафором (503 `busy` + `Retry-After`).
* Автор на сокете: query `author=`, поле `author` в `tx` или `presence`; тело `tx` без
  автора берёт автора сокета.
* Тело больше 4 МБ — `413` (сокет: ws закрывает соединение кодом 1009), транзакция с
  более чем 5000 операций — `413`. Неизвестный вид операции — `400`; операция известного
  вида, которую строгий `applyOps` не принял, — `dropped: invalid`, остальные ложатся;
  документ сверх 24 МиБ / 20 000 узлов — `dropped: invalid` с `limit` у всего, кроме `remove`.
* `dropped` в журнале и ответе — не больше 50 записей и `{more: N}`; большие операции — выжимкой.
* Мусор в несуществующий проект — `404`, а не `400`.
* Транзакция, у которой отброшены все операции, всё равно получает `seq` и пишется
  (`ops: []`): автору нужен ответ с `dropped`, идемпотентности — запись.

## Тесты

```sh
npm run test:server                                   # только сервер: memory всегда, pg — если база отвечает
TEST_DATABASE_URL=postgres://imago:imago@127.0.0.1:5432/imago_test npm run test:server
npm test                                              # весь репозиторий, серверные тесты входят
```

Без `TEST_DATABASE_URL`/`DATABASE_URL` (или если база не отвечает) прогоны над Postgres
помечаются `skip`, над памятью идут всегда. Перед прогоном с базой таблицы очищаются
(`TRUNCATE … CASCADE`) — не указывайте рабочую базу; тест миграций работает в своих
схемах (`search_path`) и удаляет их за собой.

Что покрыто (`test/server/document.test.mjs`, `test/server/storage.test.mjs`): маршруты и
коды §9.2, идемпотентность (в том числе два параллельных `POST` с одним `tx_id`), 426/400/404/413,
слияние §9.6 (`removed`, `reparented`, `cycle`, `invalid`, два `create` с одним `after`),
снимок раз в N и переигрывание журнала (`hashDoc` совпадает), «другой писатель» (запись мимо
памяти → перечитан хвост), два экземпляра над одним хранилищем, выгрузка головы и
восстановление надгробий, WebSocket (догон, живой поток обоим, `dropped` у всех, `presence`
не себе и не чаще 10/с, `left`, `gone` + хвост, транзакция во время догона), статика.
Круг 23: `hardening.test.mjs` (пределы и их сверка с клиентом, тело ошибки, chain и эпоха,
разбор tip, страницы в байтах, `head`/`lean`, семафор, прореживание снимков, снимок после
отката, предел документа, выжимка `dropped`, трассы, NOTIFY между экземплярами),
`rollback.test.mjs` (restore под двумя экземплярами с настоящими репликами `src/sync.js`),
`migrations.test.mjs` (миграция дольше дедлайна, два экземпляра на старте, откат упавшей,
заполнение chain старого журнала).
Круг 24: `presence.test.mjs` (присутствие между экземплярами, выжимка, TTL, `bye`, падение
процесса по SIGKILL, реплики с сердцебиением), `resilience.test.mjs` (обрыв LISTEN и всех
соединений экземпляра, гонка двух экземпляров, утечка комнаты, кеш кадров в байтах, прежний
клиент и `ack`, страницы по байтам, потерянные записи журнала, медленный читатель).
Нагрузочный самотест (не входит в `npm test`): `env -u NODE_OPTIONS node test/server/load.mjs`.
