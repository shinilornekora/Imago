# specs/ — черновики кругов (Spec Kit)

Spec Kit (`github/spec-kit`, `specify init --integration claude`) подключён к уже живущей
спецификации, а не вместо неё:

| Spec Kit | Imago |
|---|---|
| `.specify/memory/constitution.md` | правила проекта (принципы I–VII); выжимка из SPEC §1, §8.3, §9, §13 и практики кругов |
| feature (`specs/NNN-…/`) | **круг**: номер фичи = номер круга (`--number 72`), ветка `r<круг>-<суть>` |
| `spec.md` | что и зачем — постановка круга (потом становится разделом «Круг N» в `SPEC.md`) |
| `plan.md` | как: модули, контракты, тесты; «Constitution Check» читает конституцию |
| `tasks.md` | шаги реализации и проверок, включая обновление сайдкаров `*.llm.md` |
| нормативная спецификация | `SPEC.md` — единственный нормативный текст; `specs/` — история решений |

Круги 1–71 уже описаны в `SPEC.md` (оглавление — заголовки `## N.` и `### N.M`, «Круг N» в
названиях подразделов) и в `docs/`; задним числом в `specs/` они не переносятся.

## Как вести новый круг

1. Ветку `r<круг>-<суть>` от вершины своей цепочки PR создаём сами, затем
   `/speckit-specify <постановка>` с номером круга — навык создаёт `specs/<NNN>-<суть>/spec.md`
   и пишет путь в `.specify/feature.json` (локально, в git не идёт); веток он не создаёт.
   Вручную: `.specify/scripts/bash/create-new-feature.sh --number <круг> --short-name <суть> "<постановка>"`.
2. `/speckit-clarify` (по желанию) → `/speckit-plan` → `/speckit-tasks`.
3. `/speckit-implement`; тесты с Postgres; сайдкары изменённых файлов обновлены
   (`node tools/sidecars.mjs --changed origin/<база>`).
4. Итог переносится в `SPEC.md` новым подразделом («Круг N», раздел из своей полосы номеров);
   `spec.md` круга получает ссылку на этот раздел.
