# Схемы

Все схемы — mermaid, открываются в любом просмотрщике markdown с поддержкой mermaid
(GitHub рисует их сам).

| файл | что показывает |
|---|---|
| `01-как-есть.mermaid` | действующие элементы текущего приложения: всё в браузере, две сборки, чего нет |
| `02-в-чём-ставка.mermaid` | чем архитектура отличается от геометрического редактора: истина — структура, геометрия — функция от неё |
| `03-путь-команды-сейчас.mermaid` | путь одной команды в текущем коде: оболочка → мозг → движок → транзакция |
| `04-целевая-архитектура.mermaid` | система как она построена: два процесса — Document service (DSLR, DSLTS, Hub, приём трасс) и Orchestrator (JEV, DUIL, DSLV, LLM); поток команды в нумерации SPEC §8, ручная правка — стрелка M. К базе ходит только Document service: DUIL читает проекты-библиотеки через DSLR по HTTP, трассы Orchestrator шлёт в `/api/internal/traces` (стрелка T); команду оболочки JEV узнаёт, а исполняет клиент (событие `shell`, §10.5) |
| `05-процесс-по-фазам.mermaid` | тот же путь команды пятью фазами — для тех, кому нужен процесс, а не компоненты |
| `06-схема-базы.mermaid` | схема базы: журнал операций как истина (применённая форма, идемпотентность по tx_id, undo_of/redo_of), снимки целиком, библиотека — проект вида library с помеченными снимками; таблицы фазы 2 помечены |
| `07-ревью-целевой-архитектуры.md` | независимое ревью §8 и схем: 13 дефектов, 15 нерешённых вопросов, что не переделывать; что из этого закрыто кругом 22 — в SPEC §8.3 и §9 |

Текстовое описание целевой архитектуры и правил — `../SPEC.md`, раздел 8; контракт Document service (HTTP, WebSocket, секвенсор, правила слияния) — раздел 9; контракт Orchestrator (HTTP `/agent`, поток стадий, трассы) — раздел 10. Запуск, обновление и где работает агент — `../ЗАПУСК.md`.

Что схемы пока обещают больше кода: холодная партиция журнала (§8.3) не реализована; DUIL отдаёт библиотеки в прогон brain, но импорт мастеров как системная транзакция «обновить до v5» — открытый вопрос.
