# Критик, ось «код и надёжность», проверка круга 43 (master 717bb83)

## 1) Оценка: 9.3 (было 9.5)

`npm test` на своей базе imago_critic_code_t, без NODE_OPTIONS: **1369 тестов, pass 1369, fail 0**, 9 мин 40 с.

Снижение — не регрессия поведения: рефакторинг проверки на таблицы эквивалентен прежней. Оценку снизил за то, что новое обещание круга — «формат меняется только вместе с ENGINE_VERSION, иначе тест падает» — держится не полностью (D1).

## 2) Существенные дефекты

### D1. Отпечаток формата не видит изменений внутри функций проверки
* Где: `src/core.js` `formatSignature` (~4822). От `FIELD_RULES` в отпечаток идут только `only`/`not`; функции `check` (диапазоны `opacity`, `rotate`, оси `pos`, `props`, угол градиента 0..360 и т. п.) — нет.
* Воспроизведение (копия `core.js` с одной правкой, сверка `FORMAT_SIGNATURE`):

  | правка | отпечаток |
  |---|---|
  | `opacity` 0..2 | **тот же** |
  | `pos` без `y` | **тот же** |
  | `props` — любое значение | **тот же** |
  | угол градиента 0..720 | **тот же** |
  | `stroke.width` до 2000 | меняется (`keys`) |
  | `maxStops` 32 | меняется (`limits`) |
  | `LAYOUT_MODES` + `grid` | меняется (`enums`) |

* Мутанты T03 (`opacity` 0..2) и T13 (`pos` без `y`) **не ловит ни один тест**.
* Последствие: на правиле §8.3 стоит «наследная запись» круга 41. Если правку вроде «`opacity` до 2» внести без подъёма `ENGINE_VERSION`, тест промолчит. Тогда экземпляр прежней сборки той же версии молча пропустит новые записи как наследные и будет писать снимки без них — у разных экземпляров разойдётся документ.
* Исправление: добавить в отпечаток поведенческий раздел. Прогнать каждую `check` (и `tokenWriteProblem`, `fieldProblem`) на фиксированном корпусе проб — граничные числа, типы, лишние ключи — и хэшировать вектор «принял/отказал». Тест: правка любого диапазона меняет раздел `behavior`.
