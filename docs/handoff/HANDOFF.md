## 3. Что осталось по приложению (по приоритету)

### 3.1 Долги круга 45 (из critics/*-r44.md — читать целиком)
1. Отпечаток формата не видит изменений внутри функций проверки (opacity 0..2, pos без y, PROTECTED_PATHS, props,
   угол градиента): нужен поведенческий раздел — фиксированный корпус граничных проб через настоящие проверки,
   вектор «принял/отказал» в хэш; тесты границ opacity и pos.y. Незаконченная попытка — `wip-r45-core.patch`
   (на основе 717bb83, не проверена; заметки — notes/notes-r45-CORE.md). Плюс по критику архитектуры:
   «наследная» запись — только движка СТРОГО НИЖЕ своего; непринятая запись своей версии → голова «с пропуском»
   (без снимков) и громкий лог. Регрессия: сценарии mut.py/mut2.py/fmtloss.mjs описаны в arch-r44.md.
2. `GET /api/projects` должен отдавать `created_at` (иначе пометка сироты спасения не срабатывает, UX Д9).
3. `DELETE /api/projects/:id` только с совпадающим `create_id` и без транзакций после создания — чтобы удалить
   пустую сироту спасения; оболочка предлагает удалить её кнопкой (не молча).
4. Одинаковый порядок «Истории» у соавторов (по seq подтверждения).
5. Значок агента в шапке — в тон тосту, когда сервер агента не видит документ.
6. ORCH: busy очереди воркеров DSLV → detail {cause:'agent', queue:'workers'}; safeDetail — только неотрицательные
   целые (мутант O05); вместо «Document service ответил … 200/400» — слова для человека.
7. Поведенческий тест спасения после перезагрузки (мутант RS2).
Потом — свежий круг трёх критиков (оси и правила — process-critic-brief.md; пути в брифах были для прошлой среды).

### 3.2 «Живой» дизайн агентом (просьба пользователя; диагноз в SPEC нет — он здесь)
Лендинг таверны вышел шаблонным: сетка SaaS-лендинга, одинаковые карточки, неон из соседней доски (Tower Defense),
IBM Plex Sans/Mono. Причины: (а) токены общие на документ — лендинг унаследовал палитру игры, а brain сам отвечает
«поменять шрифт на одном экране отдельно так нельзя»; (б) конвейер «план секций → раскладка» без шага образа;
(в) валидаторы поощряют однородность, критика «шаблонно» нет; (г) нет текстур/узоров, набора выразительных шрифтов.
Делать: 1) шаг арт-направления перед раскладкой (материалы, палитра из них, пара шрифтов, мотивы, где ломать сетку);
«3 варианта» = три разных образа; 2) курируемый набор 15–20 пар Google Fonts с характером; 3) визуальный критик:
рендер в PNG → мультимодальная оценка по чек-листу → один круг доработки. Затем 4) тема на доску (токены на доску/
ветку, ENGINE_VERSION 3 + миграция) и 5) текстуры/узоры как заливка и декоративные векторы.

DOC: server/document; ORCH: server/orchestrator + src/brain.js; SHELL: app.js, index.html, styles.css, src/shell.js,

коммит → три независимых критика (только чтение, воспроизводят каждый дефект, мутационное тестирование в копии,
Playwright со скриншотами) → следующий круг. Брифы — process-common-brief.md и process-critic-brief.md
(в common-брифе строка про JEV устарела — см. §13 SPEC).
