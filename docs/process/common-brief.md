# Imago Studio — общий бриф для агентов (исполнителей и критиков)

Репозиторий: клон `shinilornekora/Imago`, рабочая ветка `imago-studio` (далее — `$REPO`; в облачной сессии
обычно `/home/claude/imago`). Своё — в отдельной ветке и через PR в `imago-studio`. Язык кода — JS (ESM,
Node 22); комментарии, строки интерфейса, коммит-сообщения и отчёты — по-русски.

## Что это
AI-first редактор макетов. DSL структурный: auto-layout без хранимой геометрии, детерминированный решатель
(`src/core.js`) считает геометрию. Пять операций: create, remove, set, move, setToken. Агент (`src/brain.js`)
превращает речь человека в патч → операции. Команды оболочки («/выделить …», «/скрыть») — открытая таблица в
клиенте (SPEC §13). Оболочка — `app.js` + `index.html` + `styles.css` (дизайн уже есть — НЕ переделывать стиль,
только встраивать новое в существующий визуальный язык).

## Архитектура (нормативно — SPEC.md §8, §9, §10, §13, §14; читать перед работой)
- CLIENT (браузер): оболочка + `core`; реплика `src/sync.js` (IndexedDB-журнал, очередь, сокет, отмена
  транзакциями, присутствие).
- NGINX: статика, `/api` и `/ws` → Document service, `/agent` → Orchestrator.
- Document service (`server/document/`): DSLR (чтение), DSLTS (секвенсор, единственный писатель), Hub
  (WebSocket). PostgreSQL: журнал операций — источник истины, снимки — производная.
- Orchestrator (`server/orchestrator/`): DUIL, DSLV, LLM, клиенты DSLR/DSLTS; к базе НЕ прикасается.
- Формат документа привязан к `ENGINE_VERSION`: отпечаток формата (таблицы + поведенческий корпус,
  SPEC §8.3, §9.20) и `FORMAT_HISTORY` в `test/core-r43.test.mjs`.
- Модель согласованности: CP по проекту, но клиент не блокируется (реплика), жертвуем актуальностью.
  Слияние не отказывает (`core.rebase`, `dropped`).

## Правила работы
- Владей ТОЛЬКО своими файлами (перечислены в задаче). Чужие файлы не трогай; если без правки чужого файла
  нельзя — опиши нужную правку в отчёте.
- Тесты: `cd $REPO && TEST_DATABASE_URL=postgres://imago:imago@127.0.0.1:5432/<своя база> env -u NODE_OPTIONS npm test`.
  Postgres: если не отвечает — `pg_ctlcluster 16 main start`. Свою базу создавай отдельно
  (`su postgres -c "createdb -O imago imago_test_<твоё-имя>"`) и удаляй за собой. Общую базу не используй:
  параллельно работают другие агенты.
- Порты для своих процессов — из выданного диапазона; останавливай процессы по PID.
- `NODE_OPTIONS` всегда снимай (`env -u NODE_OPTIONS`) — он ломает лимиты кучи воркеров.
- Playwright: `createRequire(import.meta.url)('playwright')` (ESM-импорт глобального пакета не находится),
  `chromium.launch()` без опций.
- `node_modules` в git не попадает (в том числе символической ссылкой).
- Пороги в тестах на время — относительные или без часов (счётчики), чтобы не флапали под нагрузкой.
- Без секретов в коде, логах, ответах. Сеть наружу не нужна; LLM в тестах — поддельный локальный
  HTTP-сервер (`test/orchestrator/helpers.mjs`, `startFakeLlm`).
- Финальный отчёт: что сделано (файлы), что проверено (число тестов, сценарии), что осталось и риски, какие
  правки нужны в чужих файлах. Коротко, по-русски.
